# 本地开发：设置入口与故障通知代发

本轮仅部署到授权测试服务器，不发布 GitHub Release，不移动已有标签，不提升公开版本。

面板设置前三个页面不显示高级工具；高级设置保留唯一角色切换入口。备份与诊断删除失效占位卡片。

已按用户要求删除整个国内站点 TCP 参考检测：无开关、无间隔、无三个国内目标、无复测、无随机端口检测、无封禁推断、无专用告警。历史检测配置和快照在升级时清理；旧配置导入不再恢复此功能。服务、WG隧道、本机认证监听、采集及CPU／内存／磁盘监控保留。

服务、隧道、证书和维护故障通知先直发 Bark；失败后按已配对节点顺序请求代发，第一台明确确认 Bark 受理就停止，全部失败终止并记录，不递归转发。对端需要配置同一个 Bark 服务；代发保留原收件人，服务端只允许自己的 Bark 服务地址，不接收任意 HTTP 转发请求。

配对时通过原有 HTTPS 指纹固定通道交换专用通知权限，加密保存且不暴露在面板、日志或普通导出。远端按事件ID去重、限制速率；解除配对后立即失去权限。旧配对需要双方升级后重新配对才能交换代发权限，不擅自改变原有 WG 配置。多对端按数组有序尝试，后续多出口复用此逻辑。

Bark 受理不等于手机一定收到。网络应答丢失时不能保证跨多个代发节点绝对不重复；不把超时描述为确定送达。
