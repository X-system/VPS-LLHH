# 发布说明与紧急更新

每次获准发布新版，开发者必须根据本次实际改动撰写 `docs/releases/版本号.md`，包含新增、修复、使用影响和已知限制。禁止只改版本号或用占位介绍发布。发布程序在访问 GitHub 之前检查说明，缺失、过短或没有更新内容时终止；中转端和出口端 Release 使用同一份说明。历史已发布版本和程序包保持不变。

面板直接读取对应角色 GitHub Release 的介绍，并在发现新版弹窗内显示。手动检查后，点击蓝色版本号查看内容。更新日志导出仅在更新维护页面提供，不放在发现新版本的弹窗中。

普通更新允许稍后处理或预约。`config/update-policy.json` 是发行者维护的紧急策略，默认 `required:false`，不在用户界面提供开关。确认存在必须修复的安全问题且完成测试后，发行者可在下一版设置 `required:true`；可选 `roles:["relay","exit"]` 限定角色。发布脚本将策略放入对应 Release 的隐藏标记，面板只接受通过角色、版本、下载地址和摘要校验的发布策略。

面板每天北京时间08:00检查，用户也可手动检查。获取必须更新的版本后，管理接口和界面同时锁定，只允许查看更新说明、导出更新日志、检查及立即更新；重新登录、刷新或临时断开管理器不能跳过。代理数据平面和 SSH 应急入口不受此界面锁定影响。已预约的旧更新取消，避免安装到低于安全要求的版本。发行者撤回该要求后，成功重新获取的策略也会解除限制。尚未成功获取策略的离线面板无法提前获知紧急更新。

“更新状态提醒”归为一个 Bark 可选事件，包含发现新版、高危版本、即将更新、开始、完成和失败。同一版本或任务去重；尊重用户关闭报警和事件选择，旧配置不会被强行开启。测试使用本地模拟消息，不向真实用户发送测试通知。
