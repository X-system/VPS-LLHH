# 简单管理改造验收约定

目标：只会登录 SSH 的用户，粘贴安装命令后，依靠中文网页完成后续操作。

- 安装时选择中转端或出口端；恢复安装保留原角色。
- 首次引导逐步设置账户、名称、协议、证书、Bark、可选 ATT 配对；保存进度、自动检查，不要求填写网卡、内部端口、隧道地址。
- 直出可以独立使用；只有选择 ATT 出口时才要求隧道。
- ATT 使用短时一次性邀请和双方确认配对；与未来总控通信身份分离。
- 日常导航仅首页、用户管理、流量监控、服务配置、面板设置；日志和诊断归入设置。
- 用户列表紧凑；编辑详情管理精确到每条线路的权限、到期时间、流量上限、已用流量、订阅与删除。
- 删除撤销订阅和权限，当月用量合并显示“已删除的用户”；新月不再显示旧月项目，历史总量不倒退。
- 订阅和线路名称统一配置，不使用用户名命名节点；不可用和未知状态区分，客户端更新订阅后显示状态变化。
- 自动化服从手动停止、急停和维护锁；失败有具体结果，可重试、可导出诊断，不伪装完成。
- 先本地和隔离环境验收；新购服务器由用户从零验收，现用三台不自动覆盖。
- 本轮不实现网站排行、总控后台、Codex 接入；保留接口边界，不显示虚假的接入成功。

验收顺序：独立直出与用户授权 → 用户详情和订阅 → 安装角色及可恢复引导 → 自动 ATT 配对 → 精简服务配置 → 干净 Debian 安装。


## 本轮本地验证结果

0.2.0已实现上述核心流程。本地完整回归148项，145项通过、0项失败，3项涉及Linux证书符号链接或内核状态的用例未在Windows执行。Debian12真机139项非浏览器回归全部通过，包含这3项。73个程序文件语法检查通过。

浏览器已走通一次性设置链接、账户轮换、TCP直出引导、五项导航、用户详情与删除、手机布局；两个独立HTTPS面板还走通出口引导、复制ATT密钥、请求确认、自动配置和解除配对。浏览器自动化使用模拟执行器，另外已完成两台真实VPS上的管理API配对、官方核心和真实出口请求验收。

新备份使用版本2，读取旧版本1时保留其原有权限语义；新版本逐条线路权限、日/月统计和已删除用户汇总均参与导入、回退与角色归档。角色切换后重新进入恢复引导，保留用户数据并要求明确确认启动。

本轮Debian12干净真机已完成中转端安装、重复安装、真实整机重启及中断安装恢复；随后通过正式清除数据卸载流程，再完成出口端重新安装、重复安装和真实整机重启。两个角色均检查管理服务自动恢复、账户/身份/入口保留，未开通的代理不启动。出口端安装是在卸载清理后的同一系统上完成，不宣称两次全新操作系统验收。

本轮双机实测已通过：一次性邀请与双向确认、正式域名证书、四条TCP/Hy2与直出/隧道组合、出口地址核对、经节点访问自身面板；删除WG接口时两条隧道线路拒绝连接，两条直出仍可用，恢复WG后四线重新可用。

用户管理实测通过精确两线路授权、同一凭证跨未授权线路被拒绝、停用/额度超限/删除后的重新连接拒绝、其他用户继续使用、删除旧订阅404及当月已删除流量汇总保留。

待完成：512MB实际运行、长时间稳定性与真实证书到期续签。发布方案已改为公开GitHub仓库与Release；仓库地址确认后补充真实下载链路验收。用户已明确将原有节点授权为临时开发测试资源；实际操作范围仍以当前授权为准。

实测修复了两项接口边界问题：管理器动作名允许协议名称所需的数字；TCP权限同步在明确的管理器409占用时最多重试5秒，重试耗尽仍执行原有的保护停机，其他错误不重试。

双机带真实用量重启验收已通过：两端管理与WG恢复，账户、用户精确权限和配对身份不变，线路累计不减少；中转端重启前手动关闭的线路保持关闭，明确启动后四线路再次通过出口与自身面板访问验证。异常退出的TCP实例已通过后台恢复；用户电脑上的官方Hy2客户端也验证了两条出口及正式证书。
