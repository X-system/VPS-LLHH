# 系统与发布验收计划

## 首批目标

优先Debian，先完成Debian12 amd64，再验证Debian13 amd64。两者未经完整矩阵验收前均不宣传为正式支持。

- Debian12：优先使用用户提供的干净测试VPS，直接验证安装、管理流程及整机重启；已有隔离测试结果作为补充。
- Debian13：后续目标，需要时向用户申请干净测试系统，不默认启动软件模拟虚拟机。
- Ubuntu24.04、ARM64：暂不列入支持范围，后续扩展。
- Debian testing/unstable、旧版Debian、RPM系：首版不支持，不自动尝试兼容安装。

## 每个正式目标的验收

1. 干净系统：root/sudo、架构、资源、时间、依赖、下载校验、HTTPS、随机入口。
2. 两角色：向导、配对、协议、出口、用户、证书及断线保护。
3. 权限：低权限面板、固定系统操作、秘钥权限、CSRF、限速、旧入口404。
4. 用户生命周期：添加、禁用、过期、额度耗尽、重置凭证、现有连接撤销、其他用户不受影响。
5. 统计：上传/下载方向、用户与出口归属、计数周期、重启后累计、在线定义与速度。
6. 运维：开机、自修复、手动停止、急停、磁盘/进程故障、重启限速、诊断导出。
7. 入口轮换和Bark：加密、失败重试、过期入口、无需永久备用入口、订阅不随入口变化。
8. 安装/维护：重复安装、端口占用、已有防火墙、升级与回退、角色切换、导入导出、卸载保留和清除数据。

## 当前证据与边界

本机安全/API/浏览器测试与Linux测试详情见架构文档。测试机地址、凭证、具体运行报告仅存于忽略提交的data，不放入公开仓库。

已在独立回环环境验证官方核心配置、真实出口请求、用户统计、缺WG时不绕行，以及Hy2独立HTTP认证加kick：停用A并撤销后A失败，B正常，核心PID未重启；额度耗尽拒绝重新认证。

现已补充独立后台权限和额度执行、TCP实例重建的回归，以及正式管理器在隔离网络内执行WG与防绕行规则的实际测试。正常流量、缺WG、删除防火墙后的第二层拒绝、直出不受影响、本地统计API身份隔离均已验证。

正式systemd核心已验证低权限启动、异常重启、手动停止不被恢复。管理端口修改已验证实际HTTPS、关闭旧端口与错误连接自动回退。卸载保留与恢复安装保留账户、入口、身份、用户和用量，且不更改原有Web服务与个人规则。

Debian12、Debian13隔离环境均已完成安装、登录、用户管理与整机重启持久性验收；Debian13完整协议矩阵仍待补充，安装器仅允许实验验证。完整发布包升级已覆盖正常更新、新版启动失败自动退回、先前回滚点保留与手动回滚，并校验账户、凭证及非零累计不丢失。下载由本机受限测试夹具提供，尚未验证公开GitHub下载链路。

统计后台已实际注入暂停故障，验证看门狗终止、核心联动停止及自动恢复。规则检测已覆盖链被清空但表仍存在的情形。真实域名ACME测试及正式签发、管理HTTPS证书链与域名验证已完成。Bark普通测试推送已在用户明确授权后发送，并由用户确认手机收到；该项不再待验收，不代表所有告警事件均已在真机逐项触发。实际到期续签仍待外部验收，GitHub分发暂缓。

安装恢复实测覆盖未完成安装、程序目录缺失：独立源码重新部署后保留管理员、身份、入口、用户和累计；四个管理服务正常，代理保持急停，原有网站服务不受影响。升级中突然断电的自动恢复不在当前保证范围。

真实测试发现Hy2的广泛IPv6 ACL可能导致同时有AAAA记录的域名整体被误拦，已移除该全量ACL。IPv4-only出站和内核UID防绕行负责IPv6边界，IPv6本地/链路地址ACL保留；不能通过错误的全量ACL阻断正常域名。

干净安装验证使用用户明确提供或重装的测试机；不使用现用节点代替测试。测试时默认关闭代理线路，开发源代码在D盘保留。

已验证域名证书切换时保留原IP入口、修改端口同步两个地址，非法Host和跨地址Origin被拒绝。IP使用域名证书时仍会有名称不匹配提示。测试后恢复原预览地址，代理全程关闭。

## 本轮组合验收

已通过同一宿主内的隔离客户端、中转与独立内核Debian12出口虚拟机验证：两端网页API配对、四条真实协议/出口组合、正式Hy2证书校验、用户和线路统计、在线观测、停用及额度执行、WG断开拒绝与恢复、出口虚拟机重启后WG自启及业务恢复。操作结束核对原账户和用量恢复、测试环境关闭、宿主路由和防火墙保持原样。

测试发现并修复：网络服务仍active而WG接口被删除时，启动动作可能不重建接口却报告成功。现在会重建并验证接口与保护规则；协议核心退出等待限制为10秒。客户端重连给出独立观察窗口，记录本次等待，不把连接恢复等待作为正常线路延迟。

协议核心默认会拦截部分特殊用途地址，隔离测试目标需与此兼容。本轮将公共形态的测试目标放在完全断开的测试网络内，只添加该网络及虚拟机的内部路由，不修改宿主公网路由，不放宽正式程序的地址保护规则。

用户明确授权后，已完成两台现用中转与一台出口的安装及接管，Windows官方Hy2客户端验证四条公网线路的证书、原链接兼容和预期出口；真实用量已进入新统计。现用中转的WG删除拒绝绕行、直出不受影响及接口重建恢复也已验证。

长时间运行、TCP公网完整矩阵、Debian13完整协议矩阵及真实到期续签仍待后续验收。现用服务器此轮未执行整机重启，仅开启并核对自启、自修复策略；整机重启恢复的已有证据来自隔离虚拟机。GitHub分发与私有下载授权暂缓，AI辅助配置只记录方案，不在本轮功能范围。

服务健康监控覆盖绿/黄/红/黑判定、未启用备用线路、未知状态、总控未接入、隧道故障与直出分离、故障保护停机、统计与流量上限、过期快照、只读管理请求、固定公网检测白名单及私网DNS拒绝、配置导入导出。浏览器覆盖慢速呼吸、立即悬停、手机点击、长列表与小屏滚动、监控失联后旧结果失效，以及“已开通”“流量已用完”的用户显示。

Windows无头Edge的测试进程使用软件渲染，避免某些图形环境下空白页截图与交互等待卡住；该设置仅影响自动化测试，不修改用户浏览器或面板运行方式。

节点访问自身面板须使用不带系统代理绕过规则的独立客户端验收。隔离网络覆盖 VMess TCP、Hy2 的直出和隧道四种组合，核对面板观察到的来源分别为中转地址和出口地址；不得把 ATT 的本机面板请求改走直出。直出仅允许当前管理端口，回环地址、内网和其他本机端口仍拒绝。增加本机公网地址无需重建规则；改端口后新端口可用、旧例外撤销，变更失败恢复旧规则。

隧道返回自身公网地址的连接需要在本程序的 WG 接口设置 accept_local=1、rp_filter=2，仅在中转角色创建或恢复接口时设置，不修改全局或物理网卡参数。规则检查与替换共享同一把锁，避免正常变更期间误判保护丢失。隔离验收同时检查保护链被清空能被发现、接口删除后 ATT 拒绝且直出仍正常；现用服务器不执行故障注入来代替隔离验收。

## 简化版安装验收补充

Debian12干净真机已通过中转端全新安装、重复执行安装器与实际整机重启：四项管理服务自动恢复，管理员、服务器身份及随机入口保持不变，未配置代理不会被自动开启。另通过缺少安装完成标记且网页服务停止的恢复场景：独立源码重新部署后保留身份和账户，代理急停状态持久保存。

启动自检合并元数据和根路径404检查，复用经过证书验证的TLS连接，设置单次请求和整体截止时间；拒绝证书名称不符、错误证书或公开根路径返回面板页面。测试不以延长等待替代正常启动验证。

同一真机完成正式清除数据卸载后，出口端也通过重新安装、重复安装及实际重启验收；此项属于卸载后安装，并非再次重装操作系统。Linux非浏览器回归137项全部通过。地址检测测试显式注入网卡快照，避免真机公网网卡干扰固定测试数据，并覆盖优先使用当前公网地址的行为。
